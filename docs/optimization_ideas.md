# Идеи ускорения поиска абляции (1.3.0)

Статус: черновик до фазы исследования. Обновляется по ходу анализа.
Базовая точка: Qwen3.5-0.8B, ~43 c/трейл, 200 трейлов → 3 отказа / KL 0.035 (mlp+attn);
attn-only упирается в более высокий минимум отказов.

## Где уходит время (зафиксировано по коду 1.2.0)

- `n_startup_trials = trials // 3` → при 200 трейлах **66 чисто случайных** (~33% бюджета).
- Каждый трейл оплачивает полную оценку: генерация 100 ответов × до 100 токенов (доминирует)
  + KL-форвард 100 промптов × 1 токен (дёшево).
- Нет механизма «сдаться раньше» для заведомо плохих трейлов.
- `max_response_length = 100`, хотя маркеры отказа появляются в первых ~20–40 токенах.
- Joint-поиск mlp+attn (10 измерений), хотя MLP-половина часто приходит к «не трогать».

## Каталог идей

### А. Дешевле трейл
- **A1. Многошаговый отсев (fidelity pruning)**: KL-форвард первым (дёшево), затем отказы
  на префиксах оценочного набора (25% → 50% → 100%) с ручным прунингом.
  Optuna-прунеры с multi-objective не работают → прунинг руками внутри objective.
  Критерий отсева см. в исследовании (доминирование — без ложно-прунеда).
- **A2. `max_response_length` 100 → 64** для подсчёта отказов (−25…35% генерации).
- **A3. Кэш подмножеств-ответов в полный проход** (25+50 пере-генерятся в полном проходе
  выжившего трейла). Отложено: усложнение ради ~10%.

### Б. Меньше трейлов
- **B1. `n_startup_trials` ≈ 20 вместо `trials // 3`** (66 → ~20 при 200).
- **B2. `TPESampler(group=True)`** — декомпозиционный multivariate для пространств
  с «неактивными» параметрами (плато окон).
- **B3. Silhouette-guided bounds**: из таблицы геометрии (уже считается до study) сузить
  диапазоны `max_weight_position` / `min_weight_distance` до слоёв с реальным разделением
  кластеров. У Qwen3.5-0.8B силуэт 0.07–0.13 на слоях 1–9 и 0.24–0.28 с 10-го.
- **B4. Staged search**: стадия 1 — attn-only (~40–60 трейлов), стадия 2 — MLP поверх
  замороженного attention (+ опциональный множитель max_weight attention ±20%).
  Риск жадности; компенсируется множителем.
- **B5. Warm-start из старого журнала**: enqueue Pareto-точек прошлых прогонов той же
  модели. Отложено: resume и так продолжает TPE с историей.

### В. Потолок attn-only
- **B-атт-физика**: минимум отказов attn-only выше, чем mlp+attn, — это свойство модели,
  а не поиска. Пол не сдвинуть, потолок — можно:
- **C1. `max_weight_limit`**: верхняя граница max_weight 1.5 — вероятно, ограничитель
  attn-only. Сделать конфигурируемой (2.0–2.5 для attn-only).
- **C2. Subspace rank 2–4** для attn-only (уже реализовано в 1.2.0, просто включать).
- **C3. `direction_source: mean|median`** — направление из покомпонентной медианы
  residual-векторов (робастнее к massive activations; на последнем слое Qwen |r|≈102).

### Г. Сэмплер
- **D1. Прочее**: CMA-ES/BOHB — отклонено: 10 измерений + детерминированная цель,
  TPE адекватен; выгрыш не в сэмплере.

## Результаты исследования (Optuna 4.9 изнутри + замеры)

1. **`group=True` — no-op для нас.** `GroupDecomposedSearchSpace` группирует параметры по
   тому, какие параметры встречаются вместе в трейлах; у нас пространство статическое
   (все параметры в каждом трейле) → одна группа → поведение идентично `multivariate=True`.
   Идея B2 снимается.
2. **TPE включает PRUNED-трейлы в модель** (`states = [COMPLETE, PRUNED]`). Прунеды без
   intermediate values получают фиксированный ключ сортировки `(1, 0.0)` и могут занимать
   слоты «below» (условно-хороших) без всякого смысла. **Вывод: при прунинге обязательно
   репортить промежуточное значение (счётчик отказов на шаге)** — тогда `_get_pruned_trial_score`
   = (-step, value) и прунеды ранжируются осмысленно.
3. **`study.enqueue_trial(..., skip_if_exists=True)` доступен** → управляемые стартовые
   трейлы безопасны при resume.
4. **Resume молча игнорирует смену направлений** (проверено: create_study с другими
   directions возвращает старый study без ошибки) → при смене скореров и старом журнале
   получаем криптический крах посреди прогона. Это **баг 1.2.0** (см. bugs_in_1_2_0.md);
   в 1.3.0 добавляется явная проверка.
5. **Замер стоимости оценки** (tiny llama, CPU; отношения переносятся):
   KL-форвард (100×1 ток) = 109 мс; генерация 100×100 ток = 2.80 с (**26× KL**);
   100×64 ток = 67% стоимости; префикс 25 промптов = 11%.
   → отсев «мёртвого» трейла после KL-шага экономит ~96% стоимости оценки;
   `max_response_length` 64 вместо 100 — минус треть генерации.
6. **Математика корректного отсева.** Отказы на префиксе промптов — точная нижняя граница
   полного счёта (жадное декодирование, детерминированные маркеры). Трейл гарантированно
   доминирован точкой фронта f, если `f.kl ≤ kl_трейла` и `f.refusals ≤ refusals_префикса`
   — тогда сколько ни досчитывай, фронт он не улучшит. KL-шаг: если у фронта есть точка
   с 0 отказов и `f.kl ≤ kl_трейла` — трейл мёртв уже после KL-форварда (~4% стоимости).
   Чтобы префиксные счётчики совпадали с полным проходом побатчно, шаги округляются вверх
   до сетки batch_size.
7. **Ограничение прунинга**: при включённом capability proxy фронт трёхмерный, а
   capability до полной оценки неизвестна → прунинг отключается (soundness).

## Дополнительная находка исследования

- `Trial.report` в multi-objective запрещён самим Optuna (NotImplementedError), но
  ранжирование прунед-трейлов в TPE (`_get_pruned_trial_score`) читает intermediate
  values напрямую из storage → они пишутся через
  `study._storage.set_trial_intermediate_value` с тихим фолбэком.
- Ожидающие (enqueued seed) трейлы не учитываются в `n_trials` и в нумерации:
  `executed = len(trials) - waiting`; иначе короткий прогон вообще не стартует.

## Отложено (с дизайном)

- **Staged search** (attn → заморозка → mlp + множитель attn ±20%): самый большой
  потенциальный выигрыш для mlp+attn (~90 трейлов вместо 200), но требует оркестрации
  двух стадий в одном журнале и записи стадии в бандл. Кандидат в 1.4.0.
- **Silhouette-guided bounds**: сузить `max_weight_position`/`min_weight_distance`
  по слоям с силуэтом выше порога (у Qwen3.5-0.8B — с 10-го слоя). Требует записи границ
  в журнал/бандл. Кандидат в 1.4.0.
- **Кэш префикс-генераций в полный проход выжившего трейла** (~10% экономии).


## Полевая находка (прогон Qwen3.5-0.8B, 200 трейлов, batch 128)

Multi-fidelity прунинг при batch ≥ eval-set **выключается сам**: шаги префикса
округляются вверх до сетки батча (0.25·100 → 128 ≥ 100) → расписание пусто.
Математика без кэша подмножеств (идея A3) и так проигрывает: выживший трейл
платит полный проход 2× (KL + генерация заново), мёртвый — 0.7×; при 50-70%
мёртвых суммарно выходит ~break-even или хуже. Вывод: чтобы прунинг давал
реальный выигрыш на больших батчах, нужен **кэш префикс-генераций** (A3) —
переносим из "отложено" в приоритет 1.3.x. Для текущего прогона активны:
seed-трейлы, startup 20, max-response-length 64 (все дают чистый выигрыш).
